${SITE_TITLE}

A minimal open-source scratch container image (~5 MB) that serves static files via a fully static Go binary. No OS, no shell, no external dependencies. Runs as UID 65534 (nobody).

PORT SERVE_DIR FALLBACK_DIR GET /healthz GET /version

Deploying your own content

Mount your content at /app/public/ (SERVE_DIR). The image ships baked-in default files at /app/default/ (FALLBACK_DIR). Files not found in SERVE_DIR automatically fall through to FALLBACK_DIR.

This means you can mount only the files you want to override. For example, mounting only index.html via a ConfigMap will still serve the baked-in style.css, script.js, and llms.txt from the fallback — no need to duplicate every file. Mount a full directory to replace all defaults at once.

The simplest Kubernetes pattern is a ConfigMap — name your entrypoint index.html so the server returns it for /. 

# 1. Create a ConfigMap from your HTML file
kubectl create configmap my-app \
  --from-file=index.html=my-page.html \
  -n my-namespace

# 2. Reference it in your Deployment
spec:
  volumes:
    - name: public
      configMap:
        name: my-app
  containers:
    - name: static-server
      image: ${IMAGE_REF}:latest
      ports:
        - containerPort: 8080
      readinessProbe:
        httpGet: { path: /healthz, port: 8080 }
      livenessProbe:
        httpGet: { path: /healthz, port: 8080 }
      volumeMounts:
        - name: public
          mountPath: /app/public
          readOnly: true
      securityContext:
        readOnlyRootFilesystem: true
        allowPrivilegeEscalation: false
        capabilities: { drop: [ALL] }

Deploying with dynamic metadata (initContainer pattern)

To inject deployment-specific values (canonical URL, og:url, etc.) without making the static server dynamic, run an initContainer that renders a template into a shared emptyDir before the server starts. The static server remains a pure file server; the initContainer handles one-shot configuration.

The baked-in template is available at /app/default/index.html.tpl. All identifying values are ${VAR} placeholders ready for envsubst. 

spec:
  initContainers:
    - name: configure
      image: alpine:3
      command:
        - sh
        - -c
        - |
          apk add --no-cache gettext
          envsubst < /default/index.html.tpl > /public/index.html
          cp /default/style.css /default/script.js /default/llms.txt /default/robots.txt /public/
      env:
        - name: SITE_TITLE
          value: "My App"
        - name: DESCRIPTION
          value: "My application description."
        - name: OG_URL
          value: "https://my-app.example.com/"
        - name: SOURCE_URL
          value: "https://github.com/my-org/my-app"
        - name: VENDOR
          value: "My Org"
        - name: SITE_AUTHOR_URL
          value: "https://my-org.example.com"
        - name: IMAGE_REF
          value: "my-registry.example.com/my-org/my-app"
        - name: IMAGE_URL
          value: "https://my-registry.example.com/my-org/my-app"
        - name: SCHEMA_LICENSE_URL
          value: "https://opensource.org/licenses/MIT"
        - name: SITE_KEYWORDS
          value: "my-app, kubernetes, docker"
        - name: VERSION
          value: "v1.0.0"
      volumeMounts:
        - name: default
          mountPath: /default
          readOnly: true
        - name: public
          mountPath: /public
  containers:
    - name: static-server
      image: ${IMAGE_REF}:latest
      volumeMounts:
        - name: public
          mountPath: /app/public
          readOnly: true
  volumes:
    - name: default
      emptyDir: {}              # populated from FALLBACK_DIR by a cp initContainer, or use hostPath
    - name: public
      emptyDir: {}              # initContainer writes here; static-server reads it

Multi-file sites

Use a ConfigMap with multiple keys for multi-file sites. For build-step content, use an initContainer to populate an emptyDir at startup. 

# initContainer pattern — build into /app/public before serving
spec:
  initContainers:
    - name: build
      image: node:22-alpine
      command: [sh, -c, "npm ci && npm run build && cp -r dist/* /public/"]
      volumeMounts:
        - name: public
          mountPath: /public
  containers:
    - name: static-server
      image: ${IMAGE_REF}:latest
      volumeMounts:
        - name: public
          mountPath: /app/public
  volumes:
    - name: public
      emptyDir: {}

Building and publishing

# Using the Makefile (recommended — handles all registries + OCI labels)
make build VERSION=v0.1.0            # local single-platform build
make build-multi VERSION=v0.1.0      # multi-platform push to all configured registries

# Override any metadata at build time without editing any file
make build-multi VERSION=v0.1.0 \
  SITE_TITLE="My App" \
  VENDOR="My Org" \
  SOURCE_URL=https://github.com/my-org/my-app

# Direct docker commands
docker build \
  --build-arg VERSION=v0.1.0 \
  --build-arg SITE_TITLE="My App" \
  --build-arg VENDOR="My Org" \
  --build-arg SOURCE_URL=https://github.com/my-org/my-app \
  --build-arg OG_URL=https://my-app.example.com/ \
  -t ${IMAGE_REF}:v0.1.0 .

API Reference

This section is the authoritative reference for the running server. It is derived directly from main.go and kept in sync with the source. A machine-readable version is available at /llms.txt.

HTTP Endpoints

MethodPathStatusDescription
GET / 200 / 404 Serves SERVE_DIR/index.html; falls through to FALLBACK_DIR/index.html if absent. Returns 404 if found in neither.
GET /<path> 200 / 404 Serves the file at SERVE_DIR/<path>; falls through to FALLBACK_DIR/<path> if not found. Returns 404 if the path does not exist in either filesystem, or is a directory without an index.html.
GET /healthz 200 Liveness and readiness probe. Response body: ok.
GET /version 200 Build-time version string as plain text (e.g. v0.1.0). Returns dev when built without a version flag.
GET /llms.txt 200 Machine-readable API reference for AI/LLM agents.
GET /robots.txt 200 Crawler policy: Allow: /.

Environment Variables

VariableDefaultDescription
PORT 8080 TCP port the server listens on.
SERVE_DIR /app/public Primary filesystem path to serve static files from. Mount a volume or ConfigMap here.
FALLBACK_DIR /app/default Fallback path served when a file is not found in SERVE_DIR. The image bakes default content here (index.html, style.css, script.js, llms.txt, robots.txt). Set to an empty string to disable the cascade entirely.
SPA_FALLBACK false Serve index.html (200) for unknown navigation routes (extensionless paths), enabling client-side routing and deep-link refresh. Asset requests (paths with an extension) still return 404 on miss.
CACHE_IMMUTABLE_PREFIX (empty) Path prefix whose files get Cache-Control: public, max-age=31536000, immutable (fingerprinted assets, e.g. /assets/). index.html and navigation routes get no-cache. Empty disables immutable caching.
CONTENT_SECURITY_POLICY (unset) When set, adds the Content-Security-Policy response header with this value.
PRECOMPRESSED false Serve a sibling .br/.gz asset when the client accepts that encoding and the file exists, preserving the original Content-Type.

Behaviour

  • Methods. Only GET and HEAD are accepted; any other method returns 405 with Allow: GET, HEAD.
  • SPA fallback (SPA_FALLBACK=true). An unknown navigation route — a GET whose final path segment has no extension — serves index.html with 200, so client-side routing and deep-link refresh work. Asset requests (paths with an extension) still 404 on miss, so a broken build is not masked.
  • Correct MIME types. Types are registered at startup (scratch images have no /etc/mime.types), including .wasm → application/wasm so WebAssembly streaming instantiation works.
  • Cascade filesystem. Files are resolved in SERVE_DIR first. If not found, the request falls through to FALLBACK_DIR. This enables partial overlays — mount only the files you want to customise in SERVE_DIR and let FALLBACK_DIR supply the rest.
  • Directory listing is disabled. A request for a directory path returns 404 unless that directory contains an index.html file (checked in SERVE_DIR first, then FALLBACK_DIR).
  • Graceful shutdown. On SIGTERM or SIGINT, the server stops accepting new connections and drains in-flight requests for up to 10 seconds before exiting.
  • Request timeouts. ReadTimeout 15 s, WriteTimeout 30 s, IdleTimeout 60 s.
